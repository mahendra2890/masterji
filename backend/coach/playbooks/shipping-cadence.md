# Playbook: Shipping Cadence
*(inspired by Pieter Levels' "MAKE" and his public ship-daily practice —
Masterji's own distillation)*

## BUILD dies from drift, not difficulty
Nobody abandons an MVP because the code got too hard. They abandon it in
week three, when "almost done" has been true for ten days and no outsider
has seen anything. Cadence is the antidote: the unit of progress is a
**user-visible change**, and the unit of time is **one day**.

## The day-sized slice
Every morning's declared task must end in a state someone else could see:
a page that loads, a button that does the thing, a message that sends.
"Worked on the backend" is not a state — it's weather. If a task can't
produce a visible change by tonight, it's two tasks; cut it in half and
declare the front half.

## A deadline is a feature
Levels ships projects against short, public, self-imposed deadlines — the
date does the work a boss would do. Set the launch date **before** the
build feels ready, and tell the people you talked to in VALIDATION. The
mild embarrassment of a named date is cheaper than the quiet death of an
open-ended one. Masterji's evening proof is the same
mechanism at daily scale: the clock, not the mood, decides when work is
shown.

## Momentum beats polish
Ship the ugly version of today's slice today, not the clean version
Friday. Polish is a response to a user's complaint, not to your anxiety.
When the urge to rewrite hits, that's the over-engineering playbook's
department: messy code with users beats clean code without.

## What counts as PROOF for Masterji
- A link or screenshot showing today's visible change, however small.
- The message you sent a real tester announcing it ("payments work now —
  try it").
- A dated changelog line in the repo. Three of those in a row is a
  drumbeat; a drumbeat is a product being born.

## Signals you're in cadence
- Someone outside the project sees something new most days.
- You're slightly embarrassed at each day's slice, and it ships anyway.
- The launch date is written somewhere a real person can see it.

## Signals you're drifting
- "Still working on X" three days running — the slice is too big.
- Commits without a single user-visible change behind them.
- Waiting until it's "ready to show" — ready is a decision, not a state,
  and you're letting the mood make it instead of the calendar.
