# Playbook: Scoping the Smallest Real Thing
*(inspired by Eric Ries's "The Lean Startup" and Pieter Levels' "MAKE" — Masterji's own distillation)*

## The test for every feature
One question: **does this help the next real user get the core value this
week?** If not, it goes to the "later" list. The later list is where features
go to be forgotten, and that is its job.

## Scope by subtraction
Start from the one moment your product earns its existence — the message
sent, the payment collected, the report generated. Now delete everything the
first ten users could live without:
- Accounts? A shared link or a WhatsApp number might do.
- Admin panel? You are the admin panel. Edit the database by hand.
- Payments integration? Collect via UPI and a spreadsheet first.
- Mobile app? A web page. Maybe a Google Form and your own two hands.

If the "product" for week one is you doing the work manually behind a form —
that's not cheating, that's the fastest possible test of whether anyone wants
the work done.

## The one-week rule
An MVP you can't put in front of a user within a week of starting BUILD is
not an MVP; it's a project wearing an MVP's clothes. Cut until it fits.

## What counts as PROOF for Masterji
- A link that opens: deployed page, working form, live bot — ugly is fine.
- Evidence a real user touched it: a screenshot of their message, their entry
  in your spreadsheet, their name in your logs.
- A manual "concierge" run: you did the service by hand for one real person
  and wrote down what happened.

## Signals you're building the right thing
- Users from your VALIDATION conversations are the first testers.
- You're embarrassed by how little it does, and someone uses it anyway.

## Signals you're hiding in the build
- Comparing frameworks for something with zero users.
- Building login, settings and dark mode before the core action works.
- "Refactoring" week one's code instead of showing it to person number two.
